# OneAI Features

Detailed behavior of every OneAI feature. The overview is in the [README](../README.md).

## Features

1. **Folder tree and multiple tasks (left sidebar)**
   - Each task row shows the official brand logo of its CLI (Codex, Kimi Code, OpenCode and others). The right edge of the sidebar can be dragged to resize (double-click the divider to reset), and the "Current tasks" header has a button to collapse or expand all folders at once.
   - The first level is the working folder (Git branch badge, task count, collapse state; collapsed folders also show a dot when they contain running or failed tasks). The second level is the tasks running concurrently in that folder, each with its own status light and close button. Terminals in several folders run at the same time, and switching tasks or folders never ends a terminal.
   - `Tab` moves focus across folders, tasks and close buttons, and `Enter` or `Space` activates them. The close button appears when a task row is hovered or focused (otherwise taking no space away from titles and summaries). Status dots stay static.
   - The "+" on a folder row opens a CLI menu (clicking "+" again toggles it closed; arrow keys, `Home`, `End` and `Esc` work inside the menu). Choosing a CLI starts a task in that folder immediately with the default name (`Task N`) and the CLI's default command, with no dialog. CLIs that have accounts also get a "New with <account>" entry. "Custom command and directory..." in the menu, or `Ctrl + Shift + N`, opens a dialog to set the CLI, name, command and directory. `Ctrl + Shift + T` creates a task in the current folder with the current task's CLI (and inherits its configured account when present, as does `Ctrl + Shift + N`).
   - CLI lists are sorted alphabetically by display name across the app (folder "+" menu, Home start cards, New Task dialog, Settings → CLI, and the installer), with the system terminal last. Hovering or focusing a CLI entry in the folder "+" menu shows a soft macOS glass highlight with a specular edge.
   - The second line of a task row shows the latest user message in that task's session (Claude Code, Codex, Kimi Code). A session with no message yet shows "New session · creation time", using the same offset as the top bar clock (Settings → Time). Other CLIs have no readable session file and stay single-line. It refreshes every 5 seconds, stopped tasks included. Tasks with an account read sessions from that account's config directory.
   - The task-to-session mapping is heuristic. A task restored from history is matched by session id. Other tasks are matched by "session start time is not earlier than the task creation time", assigning the session to the most recently created task with the same folder and CLI (and the same account directory). With several tasks of the same kind running concurrently in one folder the match can be wrong, and sessions you start by hand outside OneAI in the same folder can be misattributed.
   - Right-click a folder to create a task, open it in File Explorer, copy its path, clear stopped tasks, or remove it from the sidebar. Removing ends its terminals and removes its tasks, and the CLIs' history sessions are not affected.
   - The "Recent tasks" section groups local Claude Code, Codex (including `archived_sessions` and compressed `.jsonl.zst` files) and Kimi Code history sessions (including configured multi-account directories) by folder. Folders already under "Current tasks" are not repeated, with at most 8 folders and 5 sessions each. The section itself can be collapsed/expanded and each folder starts collapsed; clicking a session restores it under its original account as a current task, and right-clicking a recent folder lets you add it to the workspace, open it in File Explorer or copy its path. CLIs without readable history do not appear here.
   - The sidebar branch badge reads `.git/HEAD` to show the current branch or the first seven characters of a detached commit. It searches upward for the repository, supports worktrees and refreshes when the folder list changes, the window gains focus or 30 seconds elapse.
   - A background task gets a "Needs review" mark after 10 seconds without activity or when its terminal exits. On the collapsed rail the mark is a solid highlight, and the status dot still distinguishes idle and stopped tasks. A collapsed folder's task count changes color. Opening the task clears the mark. A CLI waiting for confirmation can also trigger the mark. Marks reset when the app restarts.
   - A task starts idle (hollow gray dot), shows running during visible output, and turns to waiting for input (solid green dot) after 4 seconds without activity. On Windows, OneAI also checks for running shell commands in the session's process tree for Claude Code, Codex, Antigravity, Kimi Code and Pi. The task stays running while a command is detected. If a check is in progress when the timer expires, OneAI waits for that check before switching to waiting or marking the task for review. Timing resumes when the last detected command ends. Detached or remote commands outside that process tree use the terminal-output rules.
   - The first 5 seconds of startup output and terminal output within 1 second of typing or resizing are filtered from the transition to running. Control sequences without visible characters also do not count. A running task has a static hollow green dot and a theme-colored neon border that respects the system reduced-motion preference. The border is visible on background tasks, while renaming, in the Dashboard, and in the collapsed sidebar. In expanded folders, a continuous connector links the folder to each running task card, with a theme-colored gradient flowing toward the card along the entire line. Reduced motion keeps the connector static. In "Settings → Reminders → Task finished sound", you can adjust the volume, disable the sound, or limit it to background tasks. The sound is on by default and plays when a task switches to waiting for input or when its terminal exits. While the window is unfocused, every task qualifies as a background task.
   - Right-click a task to run a one-click review (hidden for system terminal tasks), rename, restart (start, when stopped), copy the working directory, open the directory in File Explorer, or close the task. Opening the context menu on an AI task checks Git status on demand (skipping known non-Git folders, with a 3-second cache and no background polling) and labels "One-click review" with the uncommitted change count or `HEAD` when the working tree is clean. Hovering or clicking "One-click review" lists the available AI CLIs (including configured accounts); picking an agent reuses that status, opens a new review task in the same project folder, and automatically submits a code-review prompt with the current task context and Git change summary once the CLI is ready. Middle-click a task, or press `Ctrl + Shift + W`, to close the current task. A task whose process is still running asks for confirmation first.
   - Tasks can be reordered by dragging within their folder (not across folders), or with `Alt + ↑/↓` when a task has focus. The numbers of `Ctrl + digit` follow the order.
   - Double-click a task or press `F2` to rename it in place. `Ctrl + Tab` / `Ctrl + Shift + Tab` switch tasks, `Ctrl + 1…9` jumps to the Nth task, and `Ctrl + Shift + B` collapses the sidebar. The full list is in Settings → Shortcuts.
   - The music player is hidden by default; turn on "Show music player" in Settings → Reminders. Once on, a mini player appears at the bottom of the sidebar when the music directory contains audio files or online music has been added. The directory and online music are set in Settings → Reminders, the volume setting is remembered, and playing radio streams display "LIVE".
   - Online music: add a direct audio link, an internet radio stream or a `.m3u` / `.pls` playlist address. Tracks follow your local music in the player list. The added list shows 5 rows at most and scrolls beyond that. `.m3u8` (HLS) streams and web players that need a login are not supported. Online tracks have no spectrum data, so the bars are a decorative animation. OneAI only contacts these addresses after you add them, and "Restore defaults" keeps them.
   - Drag the handle left of a folder name to reorder folders, or focus the handle and press `Alt + ↑/↓`.
   - The top of the sidebar shows the logo, the `OneAI` name with the compact version number (taken from `package.json`) right beside it (along with the update badge when available), followed by the `All agents in one.` tagline and a time-aware greeting tied to your configured working hours (default `09:00 - 18:00`; customize working hours and each period's greeting in Settings → Time). Directly below it is a `Dashboard` navigation item (with an icon button in the collapsed rail, or `Ctrl + Shift + D`), which switches the right viewport to the full Dashboard analytics view while keeping all terminals alive in the background; clicking any task in the sidebar or the workspace strip returns immediately to its terminal.
   - **Home**, to the right of Dashboard, returns to the start page where you can create a task or reopen a recent session. Existing terminals keep running in the background.
   - The sidebar button at the left end of the top bar collapses or expands the navigation. The state is saved and terminals keep running. The collapsed rail stacks the Dashboard and Home icons above the folder and task buttons, with Add folder, Settings and Expand at the bottom.

   - Task switching preserves the running or waiting status of an existing terminal. Press `Esc` to close the task context menu and return focus to the task row. The history drawer matches open tasks by CLI, account, and session ID.
   - Drag the sidebar's right edge to resize it. Losing window focus or pressing `Esc` cancels the drag. With the resize handle focused, use the left and right arrows to change the width, or press `Enter` to restore the default.

2. **Two-line status bar below the terminal (quota, usage, resources, clock)**
   - The status bar shares the terminal's background and sits flush against it.
   - The top row shows task status, model and reasoning level, `5h limit:`, `Weekly limit:`, the refresh button, and the clock. The bottom row shows session tokens, cache hit rate, cost, `Ctx`, and machine-wide `CPU / GPU / Mem / Net`.
   - The task status is always in English, with `Free` for an idle terminal. In Chinese, the clock shows the full weekday, such as `星期一`.
   - When Codex has no session usage to display, the lower left shows `--` for token counts, cache hit rate, and context usage. At narrow widths, token counts collapse to a total and context usage can be hidden.
   - `5h limit:`, `Weekly limit:`, and `Ctx` share the same square brackets and dotted track. The two quota bars fill to the remaining percentage, with labels such as `88% left (resets 06:43)` and `80% left (resets 20:52 on 30 Nov)`. Reset times use the system time zone. Unknown quota shows a dotted track and `--`. The `Ctx` bar fills to the used percentage and turns yellow at 65% and red at 85%.
   - No popups, no floating cards, no overlays. It includes a countdown and a minimal refresh control. Settings → Time → Show status bar hides the whole bar and gives the terminal two more rows.
   - Search, clear screen, restart, and log export sit next to the truncated task name. Restart is disabled while a task is starting. As the status bar narrows, it hides the clock date and reset times first, then other details as space runs out. At narrow widths, the quota labels shorten to `5h:` and `7d:`. Hover over a quota to see its reset time.
   - With no terminal task selected, or on the Dashboard, the status bar keeps only system resources and the clock; task status, quota and the refresh button are hidden. The 5-hour and 7-day figures show the selected account's remaining quota. Codex identifies its windows by duration. Missing or expired quota snapshots display `--` until a usable reading is available. Antigravity matches the selected model to its reported quota group and leaves the quota unknown if the group cannot be identified.
   - For a ready Codex, Claude Code, Kimi Code, OpenCode, Antigravity or Pi task, click the model in the status bar and confirm that the CLI prompt is empty. The model picker opens in the active terminal. If Codex session usage lacks model information, the status bar keeps the available model and effort from the quota snapshot.
   - The status bar clock shows system time by default. Settings → Time lets you add an offset of -24 to 24 hours.
   - Codex shows model, reasoning level, and usage from the matched task log. A restored task matches by session ID, while a new task can use an unambiguous folder and start-time match. When a new task's session cannot be identified, OneAI selects the main session with the latest usage event in the recent logs for the same account and project and labels the usage `Recent`. In a project with parallel sessions, this usage can come from another terminal. The top row then shows the configured model and reasoning level. Claude Code's default account uses the shared statusLine snapshot and applies the `Recent` label when its session ID cannot be matched to the task. Pi and Antigravity also label their latest-session usage `Recent`. The label stays in English across interface languages. `Tokens` shows cumulative uncached input, output and cache usage, and `Cache` shows the read hit rate. The `Ctx` tooltip identifies estimates based on the latest request.
   - The right side of the status bar's bottom row updates machine-wide `CPU / GPU / Mem / Net` every 2 seconds. GPU sampling runs independently every 5 seconds and shows the busiest engine across all GPUs, or `--` if no sample is available. Sampling pauses while the window is hidden or minimized. Memory uses GiB, and network rates use B/s, KiB/s or MiB/s for active physical adapters.

   - The native title bar is hidden. The top bar and the sidebar brand header drag the window, and the minimize / maximize / close buttons are at the top right, with color and height following the theme and UI scale. Window size, position, maximized state and theme background color are saved and restored after the first frame is ready, without flashing a blank frame on launch.
   - While the active task is running, a theme-colored macOS glass shimmer sweeps gently along a full-width track just below the bottom edge of the top bar (positioned below the window-controls overlay so it is not clipped on the right); it fades out when the task is idle, stopped, or when viewing the Dashboard, and respects the system reduced-motion preference.
   - With no active task, the left of the top bar shows the folder and Git branch where a new task will start. The middle area lists the 3 most recent history sessions (click to restore) and a new-task button for each CLI.
   - The history button at the right of the top bar (or `Ctrl + Shift + H`) opens the history drawer. It reads both default and configured account directories (including Codex `sessions`, `archived_sessions` and `.jsonl.zst` archives), grouped into Today / Yesterday / Earlier with folder name, Git branch, account name and relative time. Sessions already open in the sidebar are marked "Open", and clicking restores the session with its original account. You can filter by CLI, search, and delete (deleting also removes the local session file).
   - The explorer button at the far right of the top bar (or `Ctrl + Shift + E`) slides out a right-hand project directory tree drawer overlaid above the terminal (never resizing or disturbing active terminals). It lazily lists the active task's working directory (or the current folder when no task is active) one level at a time, sorting folders before files in natural order with indent guides and file-type icons (dotfiles and common noise directories like `node_modules`, `.git`, and `dist` are dimmed; each directory caps at 500 entries and blocks escaping or cyclic symlinks). It remembers expanded folders per project and supports filtering loaded nodes, refreshing, collapsing all, clicking a file to open the right-side preview panel, or using row quick actions / right-click menu to insert a safely quoted relative path into the active terminal, copy paths, or reveal items in File Explorer.
   - On file rows, **Copy file** appears right after **Copy relative path**. Click it, then press `Ctrl + V` in the destination folder in Windows File Explorer to paste the file.
   - The branch badge at the top of the project tree opens a list of local branches. It uses the installed Git to switch branches and refreshes the tree after a successful switch. If Git refuses the switch to protect local files, the drawer shows the reason.
   - The **Git commit** button next to the branch badge shows the number of uncommitted changes and opens a commit dialog listing changed files (non-conflicting files checked by default) with a read-only diff viewer. Enter a commit message (or press `Ctrl + Enter`) to commit only the checked files locally without pushing, while preserving staged changes on unchecked files. Unresolved merge conflicts block committing and offer a shortcut to the conflict diff dialog.
   - The **Git conflict diff** button next to the branch badge lists unresolved files and displays each file's combined diff. The first two columns compare the working file with the two conflicting versions. Refresh after resolving conflicts in your editor or terminal.
   - Pressing `Ctrl + Shift + U` still opens the legacy "Weekly usage" panel. It reads local session records of Claude Code, Codex, Antigravity and Pi, including the directories of configured accounts. Codex is read from both `sessions` and `archived_sessions`, including compressed `.jsonl.zst` files, and Codex auto-review child sessions are listed at the end of the Codex group, marked "Child session". Top overview cards show weekly requests (with single-day peak), total Tokens (input / output breakdown), cache share and active days (with a 7-day strip), followed by a CLI Token share bar. Rows are grouped CLI → account → model, each group with request and input / output / cache / total Token subtotals, a collapse button on each CLI category, plus one-click Collapse all / Expand all and Refresh buttons. A CLI that has only the default account does not show the account level. Account names come from Settings → Accounts, and the default account is shown as "Default account". Antigravity and Pi cannot tell accounts apart, so they all count under the default account. Below the table is a 26-week daily request heatmap similar to the GitHub contribution graph (darker means more requests that day, and hovering shows the requests per CLI and account both in the header readout and tooltip). A request is one model reply. Antigravity records have no model field, so the model name is inferred from `<USER_SETTINGS_CHANGE>` switch records at the end of `USER_INPUT` steps inside the session. Kimi Code and OpenCode are not counted yet, for lack of verifiable local session samples. Conversations that exist only in Codex's SQLite thread store (`thread_history_1.sqlite`) without a session file are not counted either. The first open has to decompress history sessions and can take a few seconds, after which results come from a cache. The machine keeps session records for a limited time, so earlier dates show as empty.
   - The sidebar `Dashboard` item (or `Ctrl + Shift + D`) opens the full analytics Dashboard: supports five time ranges (`Overview` / `Today` / `7 days` / `Last 30 days` / `All`) plus cross-filtering by Agent, Project, and Account; four KPI cards for total tokens (with period coverage check and micro sparkline), deduplicated active sessions, published API-equivalent cost estimates (using native logged cost for Pi when present, and marking internal/unrecognized models as "Unpriced" while tracking price coverage), and input cache hit rate; a rolling 12-month daily activity heatmap with hatched cells for uncovered dates; a switchable monthly/daily trend bar chart (`Token` / `Cost` / `Session`, stacked by agent or total); a clickable Top 5 breakdown card (`By Agent` / `By model` / `By project` / `By account`); a token composition donut chart; a live Account quotas snapshot (including all Antigravity model groups plus Codex / Claude Code / Kimi Code accounts); a sortable model details table; and a workspace task quick-jump strip.

   - The Dashboard header keeps the title, actions, data coverage, time range, and filters visible while the analytics below scroll.
   - Dashboard counts a Codex session once per account when both the active and archived directories contain a copy. For Pi, it uses the logged cost for each request when available and estimates missing costs for models with known rates. Click a model in Top 5 to filter the charts and table to that model. Log coverage starts with the earliest matching record, and the `All` trend includes every month in the selected history.

3. **High-performance keep-alive terminal viewport**
   - Built on `@xterm/xterm` and the native Windows ConPTY driver (`node-pty`).
   - Native PTYs run in a shared worker. Output pauses at a high-water mark until the terminal parser acknowledges consumption, including hidden sessions. Usage caches are persisted per session file in batches; summary scans reuse unchanged directory listings.
   - Paths in terminal output that point to real files inside the task's working directory (absolute, relative, quoted, or extensionless build files like `Dockerfile` / `Makefile`, optionally with `:line`, `:line:col` or `(line,col)`) are rendered as links. `Ctrl` + click opens a read-only preview panel on the right of the terminal, and URLs also open with `Ctrl` + click (Settings → Terminal also offers "Open links with a single click", off by default). The panel supports text and images; its width is draggable, persisted across launches, resets on double-clicking the divider, and automatically reserves space for the terminal in narrow windows. Common code files (including JS/TS/TSX, Python, JSON, HTML/CSS, Markdown, Dockerfile, shell scripts and PowerShell) have theme-aware syntax highlighting for keywords, strings, comments and numbers. Unknown file types, large minified files and text over 1 MB stay plain text; syntax highlighting does not diagnose code errors. Text previews carry a VS Code style code minimap on the right that shows the visible range, and clicking or dragging it scrolls quickly. It can be toggled in Settings → Terminal → File preview (on by default). With a line number the preview jumps to and highlights that line. Preview text can be selected and copied, and clicking the path again or the refresh button re-reads the file. Text over 1 MB, images over 5 MB, binary files and files outside the working directory are not previewed; the exceptions are screenshots pasted into the terminal (`%TEMP%\OneAI_Images`) and image files dropped or pasted into the terminal during the current run. When the terminal holds more than one screen, a back-to-top button appears, and a back-to-bottom button appears while you are scrolled up. Claude Code's fullscreen mode draws on the alternate screen and handles its own scrolling; there, a back-to-top button at the top right of the terminal sends it `Ctrl+Home` (jump to the start of the conversation). Settings → Terminal has a Smooth scrolling switch (off by default).
   - In built-in AI CLI tasks, `Shift + Enter` inserts a newline in the input box (system terminal and custom CLI tasks keep the normal Enter). `Ctrl + Shift + F` searches terminal content, highlights all matches and shows the match count.
   - Exported and copied session text is taken from what the terminal actually renders, scrollback included (up to 5000 lines).
   - Copying a selection shows a short "Copied" notice, and pasting shows "Pasted" ("Pasted the image path" for a screenshot, or a notice when the clipboard is empty or unreadable). Unless single-click links are enabled, links only show the pointer cursor while `Ctrl` is held. When you scroll up into history, a "Back to bottom" button appears and changes to "New output, back to bottom" if output arrived meanwhile. Dropped files are pasted as quoted paths followed by a space. Restarting resets the terminal modes left by the old process.
   - Closing the window quits OneAI by default and asks for confirmation if terminal processes are running. Turn on **Settings → Appearance → Window behavior → Hide to the system tray on close** to keep terminals running when you close the window. Double-click the Windows tray icon to restore the window, or right-click it and choose **Quit OneAI** to quit with the same terminal confirmation.
   - When you switch sessions and subtasks in the sidebar, the DOM is shown and hidden rather than destroyed, so processes keep running and output and context are never interrupted or lost.
   - It adapts to window resizing and recalculates character rows and columns automatically.

4. **Working folders**
   - "Add folder" at the bottom of the sidebar adds a local folder. It only adds, and never ends terminals that are already running. With no active task, new tasks start in the most recently used folder by default.
   - The folder list, the tasks of each folder and the current selection are saved together and restored after a restart (tasks come back as stopped and start when selected).
   - When upgrading from an older version, the first launch merges the old per-folder task stores by directory (empty workspaces are not imported). The old data is kept as is and not deleted.
   - The "Working directory" in the new task dialog can be changed to another folder, and the task then appears under that folder.

5. **Appearance, Glass Material, and Themes**
   - OneAI uses the latest macOS Liquid Glass visual language by default: navigation and overlay chrome (sidebar, top bar, modals, drawers, context menus, and Dashboard cards) feature translucent frosted surfaces, subtle top specular highlights, and soft shadows while keeping the terminal and code preview solid for readability. The default Light and Dark palettes use macOS neutral tones and Apple System Blue accents.
   - The settings button at the bottom left opens Settings → Appearance to choose "System", "Light", or "Dark", plus the macOS 27-style three-tier "Glass material" setting (Clear glass / Tinted glass / Solid, defaulting to Tinted glass and automatically falling back to Solid when reduced transparency is enabled). Changes take effect immediately and are saved locally, and "System" follows the OS appearance.
   - **Workspace background & built-in macOS wallpapers**: Settings → Appearance → Workspace background includes 6 built-in macOS-style wallpapers (Tahoe Lake, Sequoia Sunrise, Sonoma Horizon, Ventura Glow, Monterey Dusk, Big Sur Coast), supports selecting a custom local image (PNG / JPG / WebP / GIF / BMP / AVIF, up to 15 MB), or switching back to None (theme color). When a background is enabled, you can adjust Background visibility (5%–85%) and Background blur (0–24 px), letting the wallpaper shine through the Liquid Glass chrome and transparent terminal.
   - **Workspace rain & snow effects**: Settings → Appearance provides independent toggleable layered ambient rain and snow effects across the entire workspace (`pointer-events: none`, never blocking clicks or selection). Workspace rain defaults to On (35%) and offers an on/off switch, 5 quick presets (Off / Light / Medium / Heavy / Storm), and a `0%–100%` slider; Workspace snow renders three depth layers of soft snow and rotating hexagonal ice crystals with theme-aware colors, defaults to Off, and offers an on/off switch, 5 quick presets (Off / Light / Medium / Heavy / Blizzard), and a `0%–100%` slider. Turning either off or hiding the window stops its animation with zero idle overhead, and reduced motion is respected.
   - Settings → Appearance also has eye-care palettes (Bean Green, Parchment, Lavender, Mist Gray, Warm Night, Arctic Gray Blue, Forest Night, Ink Night) and editor palettes: Darcula, Sublime Material, the built-in Sublime Text themes Monokai, Mariana, Breakers, Solarized Dark, Solarized Light and Cobalt, the bundled IntelliJ IDEA themes IntelliJ Light, IDEA Light, IDEA Dark (new UI) and IDEA High Contrast, Kiro IDE's Kiro Dark and Kiro Light, and Atom's One Dark. Terminal colors switch along with them.
   - Interface colors are all driven by semantic color variables. Task names and main quota text use 13px, and secondary text is at least 12px (at the default UI scale).

6. **Multiple accounts (Codex, Claude Code, Kimi Code)**
   - Settings → Accounts lets you add several accounts for each of these three CLIs. An account is an independent config directory (credentials and session records both live in it). When a task starts, `CODEX_HOME`, `CLAUDE_CONFIG_DIR` and `KIMI_CODE_HOME` are injected respectively, and a missing directory is created automatically. Optional extra environment variables (such as a proxy) are stored as plain text in the local app settings, so do not put secrets there.
   - "Log in" on an account opens a new terminal task in that account's environment running `codex login` / `claude auth login` / `kimi login`. The login state in the list comes from `codex login status` / `claude auth status`. Kimi Code has no status command, so OneAI only checks whether the credentials file exists. OneAI never copies or reads credentials.
   - The new task dialog lets you pick an account, and in the folder "+" menu every CLI with accounts gets a "New with <account>" entry. The task row and the top bar breadcrumb show the account name. A restart keeps the account the task is bound to. If the account configuration is deleted, the task refuses to start and does not fall back to the default account. "Restore defaults" does not clear accounts.
   - Status bar quota follows the task's account. Codex and Kimi Code read from that account's directory. For a non-default Claude Code account, only the model and reasoning level are shown and quota reads "--", because quota comes from a shared statusLine snapshot that cannot tell accounts apart.

7. **Work-time reminder**
   - After OneAI has been open for the set time (1 hour by default, adjustable from 1 to 12 hours), a break reminder dialog appears that must be closed manually, and by default a voice message is read out once. Settings → Reminders adjusts the duration or turns off the voice, and the dialog still appears. Closing the app resets the timer.

8. **CLI detection, one-click installer and custom CLIs**
   - On startup OneAI looks up the commands of the 26 CLIs it knows (the list is in `src/main/known-clis.json`, including command aliases such as `agent` / `cursor-agent` and `kilo` / `kilocode`, all with official vector brand logos) on this machine's `PATH` and only offers the installed ones in the new task menu, the empty state and the history filter. The system terminal is always available.
   - The welcome page, Settings → CLI ("Install common CLIs"), and the Home empty state ("Install more CLIs" when featured tools are missing) open a two-column installer: the left pane shows a 12-CLI showcase wall and detected status, and the right pane filters out already-installed CLIs to list missing tools from all 12 featured CLIs (Antigravity, Claude Code, Codex, Cursor Agent, Gemini CLI, GitHub Copilot, Grok Build, Kimi Code, Kiro CLI, OpenCode, Pi, and Qwen Code) in alphabetical order (showing up to 5 cards at a time with an internal scrollbar when more remain to keep the dialog compact) for multi-select serial installation via their official Windows commands (PowerShell script / npm / WinGet), with live output logs, copyable commands, retry, and automatic Windows `PATH` refresh without restarting OneAI. When selecting a CLI that requires Git for Windows (Claude Code, Cursor Agent, or Kimi Code) while Git is missing, or one that requires Node.js (Pi 22.19.0+, Gemini CLI 20.0.0+, or OpenCode) while Node.js is missing or outdated, a dynamic install reminder with an official download link is shown.
   - Settings → CLI lists every known CLI with its detection state (Installed / Not found) and a Detect again button (which also refreshes Windows `PATH`), so a newly installed CLI shows up without restarting.
   - A CLI that is not on the list can be added under Settings → CLI as a custom CLI: a name and a start command (arguments allowed, for example `mycli --model fast`). It appears in the folder "+" menu with a generic terminal icon and runs in PowerShell, so `.cmd` and `.ps1` launchers work. It is detected on `PATH` like the others and hidden while the command is missing. Deleting a custom CLI closes and removes its tasks.
   - Quota, task summaries, session history, usage statistics and multiple accounts depend on each CLI's local session format, so they are only provided for the built-in CLIs.

9. **Language and first-run guide**
   - The first launch offers English, Simplified Chinese and Traditional Chinese. The system language determines the initial selection, with Traditional Chinese preselected for Traditional-script Chinese or Chinese locales in Taiwan, Hong Kong and Macao without an explicit script. After you confirm, the two-column welcome page shows the 12 popular CLI icons, the default folder, and multi-select installation for any missing featured CLIs (or a ready summary when all 12 are already installed). You can switch languages later in Settings → Appearance.
   - Settings → Appearance switches the language at any time and takes effect immediately.
   - A new installation starts empty: no sample tasks are created, and the default folder is your user home directory until you add your own folders.
   - Settings → Time can hide the date in the status bar clock. The date and weekday appear by default and collapse automatically when the status bar is narrow. Both Chinese interfaces also show the lunar date.

10. **Software updates (GitHub Releases)**
   - About 6 seconds after launch, OneAI silently checks GitHub Releases for a newer version in the background without downloading automatically, and stays silent when offline. You can toggle "Check for updates on startup" or trigger a manual check anytime in Settings → About.
   - When an update is available, a badge appears next to the version in the sidebar header (and in the collapsed sidebar footer). Clicking it opens the update dialog with version details, release notes, "Skip this version", and a fallback link to the GitHub Releases page.
   - Installed Windows builds support in-app download with live progress and speed, followed by "Restart and install" (asking for confirmation if terminal sessions are running) or "Later" to install on exit. Portable builds, dev mode, or releases without `latest.yml` fall back cleanly to browser download.
