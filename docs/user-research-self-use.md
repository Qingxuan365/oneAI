# OneAI 自用研究计划

## 目标

找出 OneAI 日常使用中最耗时、最打断思路的几个点，决定下一步先改什么。

## 方法与周期

自用日志加典型任务走查，持续 1～2 周，不招募外部参与者。

## 使用日志模板

每天结束时记一条：

```text
日期：
今天开了几个任务（按 CLI 分）：
卡住或绕路的步骤：
临时靠别的工具补上的事（如另开 PowerShell、手动找历史）：
一句话感受：
```

## 典型任务走查

每项自己计时，记录步骤数和卡点。

| 编号 | 任务 | 步骤数 | 用时 | 卡点 |
|---|---|---|---|---|
| T1 | 启动应用并恢复昨天的工作 | | | |
| T2 | 新建任务并切到另一个 CLI | | | |
| T3 | 从历史会话恢复一次对话 | | | |
| T4 | 并行 3 个以上任务时查看状态和额度 | | | |

对照问题：这些事在 OneAI 里做，是否比直接开多个 PowerShell 窗口更快？不比它快的功能，价值存疑。

## 待验证假设

| 假设 | 判断依据 | 结论 |
|---|---|---|
| 侧栏按 CLI 分组比按项目分组更顺手 | 切换任务时是否经常找不到目标 | |
| 启动时检测一次 CLI 足够 | 是否出现装了新 CLI 却没显示 | |
| 历史恢复是高频功能 | 两周内使用次数 | |
| 单行额度文字够用 | 是否因看不清额度去别处查 | |
| 状态标识能判断哪个任务在等我 | 是否仍需逐个点开确认 | |

## 复盘产出

两周后整理成一页：

1. 高频动作清单（按使用次数）。
2. 卡点排序（按影响和改动成本）。
3. 要加、要砍的功能。
4. 确认后的事项再写入 `ROADMAP.md`。
